# Warface Preset Generator

Генератор Lua-инвентаря по ресурсам клиента Warface. Каталог в репозитории обновлён до **билда 729**.

Сайт работает целиком в браузере: поиск по названию/ID, четыре класса, камуфляжи, совместимые модули с изображениями, облики и броня, случайная генерация, мета по народному голосованию, скачивание Lua и сохранение/открытие сборки в JSON. Последняя сборка сохраняется в браузере.

## Открыть локально

Нужен Python 3.10 или новее. Из папки проекта:

```powershell
python -m http.server 8766 --bind 127.0.0.1
```

Открой http://127.0.0.1:8766. Открытие index.html через file:// не поддерживает загрузку каталога.

## Обновить каталог из клиента

Распакованные ресурсы остаются на компьютере. Исходные XML и DDS в репозиторий копировать не нужно.

```powershell
python -m pip install -r requirements.txt
python parse_client.py --source-root "C:UsersРоманDesktopBSW" --build 729
```

Ожидаются папки GameData 729, Other 729 и Russian 729. Можно указать пути отдельно:

```powershell
python parse_client.py --build 729 --gamedata "D:ClientGameData" --other "D:ClientOther" --russian "D:ClientRussian"
```

Параметры:

- `--output PATH` — папка назначения; по умолчанию папка проекта.
- `--workers 16` — число потоков чтения XML. Одновременно декодируются не более четырёх атласов.
- `--no-images` — собрать каталог без извлечения изображений.
- `--strict` — остановиться при некорректном XML.

Команды `node parse_weapons.js` и `node parse_skins.js` оставлены как совместимые входы в общий парсер.

## Что делает парсер

- Рекурсивно читает оружие, модули, броню, облики, боеприпасы и архетипы из `GameData/items`.
- Связывает магазинную оболочку `shop_item/content/item` с **игровым ID** оружия. В Lua используется игровой ID, а не ID покупки.
- Читает словари `Russian/languages`; использует translation, затем original. Повторяющиеся ключи разрешаются в стабильном порядке файлов и записываются в отчёт.
- Наследует скалярные параметры settings через archetype. Параметры показываются как данные конфигов; симуляция движка и расчёт итогового урона не выполняются.
- Разделяет оружейные варианты и материалы камуфляжей. Материал связывается с настоящим конфигом weapon_skin, его названием и иконкой.
- Сохраняет совместимость по sockets/support. В каждом слоте выбирается один модуль. Внутренние части модели включаются только для материала, который их активирует, и не засоряют панель выбора. Служебные эффекты, стикеры и заполнители perk_a/perk_b не выдаются за физические модули.
- Служебные AI-подкаталоги не попадают в оружейный каталог. Тестовые, учебные и консольные варианты помечаются internal и скрываются в интерфейсе.
- Читает UI/image и image_set, находит DDS/PNG по виртуальному пути .tif, вырезает заданный прямоугольник, убирает прозрачные поля и сохраняет WebP. Одинаковые изображения используют один файл. Отдельные обрезки сохраняются локально в assets/icons (не включаются в Git), а сайт использует компактные атласы assets/atlases.
- Неразрешённые ссылки, отсутствующие переводы/иконки и ошибочные прямоугольники перечисляются в `data/build-report.json`. При отсутствии иконки сайт показывает подпись, не подставляет изображение другого предмета.

Игровые файлы содержат также неиспользуемые и тестовые определения. Наличие предмета в каталоге не означает его доступность на сервере. Генератор проверяет ссылки и формат, но не запускался внутри игрового клиента.

## Народная мета

`config/meta.json` содержит 88 позиций из предоставленных тир-листов: класс, название, точные игровые ID, тир S/A/B/C/D и оценку. Для объединённых позиций сохранены оба ID (Type 97/97B, АС «Вал»/Custom и варианты Special).

При разборе клиента каждый ID и его класс проверяются. Неизвестный ID останавливает сборку. Оценки относятся к предоставленному голосованию, не вычисляются из характеристик. Кнопка «Пресет из меты» использует выбранный диапазон тиров; по умолчанию S–A.

## Структура проекта

| Путь | Содержимое |
| --- | --- |
| index.html, src/styles.css | интерфейс |
| src/app.js | поиск, карточки, состояние сборки, импорт/скачивание |
| src/core.js | проверка совместимости, случайная генерация и экспорт Lua |
| parse_client.py | общий парсер клиента |
| parser/icons.py, parser/sprites.py | извлечение, обрезка и упаковка изображений в атласы |
| config/meta.json | народный тир-лист и сопоставление ID |
| data/catalog.json, data/catalog-parts/*.json | индекс и небольшие файлы каталога для сайта |
| data/settings/*.json | полные скалярные параметры оружия по категориям; не загружаются при открытии сайта |
| data/icon-manifest.json, data/icon-manifests/*.json | индекс и происхождение извлечённых иконок |
| data/build-report.json | ошибки/неразрешённые ссылки и статистика |
| data/all_weapons.json, data/all_skins.json | локальные совместимые выгрузки для старых потребителей; генерируются парсером, в Git не включаются |
| data/weapons, data/skins, items.xml, data/items.* | прежний снимок исходных данных; сайт их больше не использует |
| tests | проверки экспорта, совместимости и парсера |
| tools/package_site.py | сборка компактного статического сайта в _site |

## GitHub Pages и изображения

PNG/WebP можно хранить прямо в репозитории и публиковать через GitHub Pages. Сайт загружает иконки относительными путями, поэтому работает и в подпапке `/preset-generator_v2/`.

[Лимиты Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits): опубликованный сайт — не больше 1 ГБ. Текущие иконки занимают около 60 МБ. Исходные атласы и node_modules в опубликованный сайт не включаются.

Для существующего Pages можно оставить публикацию из корня ветки main: сайт уже статический, сборка не обязательна. Для отдельного артефакта:

```powershell
python tools/package_site.py
```

Папка _site содержит только HTML, CSS/JS, каталог и иконки.

## Проверки

```powershell
npm test
npm run check
python -m unittest discover -s tests -p "test_*.py"
```

Для Node-проверок нужен Node.js 20 или новее; npm install не требуется. Python-тестам изображений нужен Pillow из requirements.txt.
